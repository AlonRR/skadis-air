# A QA sweep of the page (23 Oct 2026)

The owner asked for it: "have multiple haiku agents run qa on all the features and options one by one to find bugs."
Four agents each drove the development page (<https://alonrr.github.io/skadis-air/dev/>, `main` at `23916b4`) in a
headless Chromium, one feature group each, every option one at a time, downloading each part and checking it is a real
STL (its size and triangle count agree). They changed nothing. Their scripts, screenshots and downloads were kept with
the session, not in the repository. Every finding below repeated on a second run unless marked otherwise; each is the
agents' (relayed) until its fix's failing test reproduces it.

## Counts

| Group | Checks | Passed | Files checked |
| --- | --- | --- | --- |
| Boards and sizes | 149 scripted cases, about 30 probes | 126 | 78 STLs, all valid |
| Sides, seams, walls, print list, printers, formats | 87 cases, 10 probes | 80 | every download valid |
| Mounting | 215 runs (a 120-case matrix of board x screw holes x standoffs x seams x sides, the Advanced sweeps) | 191 | every STL valid |
| Connectors, test prints, the page's features | 87 checks | 76 | 25 connector STLs, all valid |

No page error and no console error in any case.

Not counted: a large skeleton build stalled only while one agent's script observed every change on the page with a
`MutationObserver`; without it the same build finished in about 21 s, twice. The theme button reads "Dark theme" in
both themes, its pressed state saying which is on; the width limit is written "1000000 mm".

Q1 to Q13 are fixed, one commit each with a failing test first (23 Oct 2026, landed at `7d95a8f`; C400 to C406, and
the CHANGELOG's Unreleased). Q3's cause: the tiling assumed a panel could be turned on the bed and nothing turned it.
Q6's: a core wider than the 3 mm edge band made the band's widening negative, so Core width is now 0.8 to 3 mm. Q14 and
Q15 wait on D371 and D372 in [`status.md`](../status.md).
